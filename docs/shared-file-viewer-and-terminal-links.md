# Shared file viewer and terminal links

Shared files have **View** and **Download** actions in the conversation and terminal downloads list. Text opens inside a themed dialog. Markdown (`.md`, `.markdown`, `.mdown`, `.mkd`) opens rendered, with **Rendered** and **Text** buttons to switch views without another download. Closing the viewer returns to the file list.

The viewer reuses the existing [Markdig](https://github.com/xoofx/markdig) dependency. It uses a file-specific pipeline for headings, tables, task lists, emphasis, autolinks and fenced code; raw HTML, generic HTML attributes and executable media extensions are disabled. Text view uses Blazor text escaping. Explicit web links open a separate tab with opener/referrer isolation. Unavailable relative links are neutralized rather than navigating the Manager. Existing fragment links remain local to the rendered document.

The preview endpoint requires the same conversation read permission as downloads, returns JSON rather than inline file content, and sends private/no-store and nosniff headers. Reads are bounded to 512 KiB plus one byte, including a file growing during the read. UTF-8 and BOM-marked UTF-16 are supported. Invalid encodings, binary control characters and oversized files show a short explanation with the original Download action. Opening a preview never changes the shared original. Initial loading and failed requests use the standard placeholder and Retry flow.

Terminal links use [xterm's link handling](https://xtermjs.org/docs/guides/link-handling/) for both ordinary URLs and named OSC 8 links. Each terminal installs its own web-links addon and OSC 8 handler. Only absolute HTTP(S) URLs are opened. A short phone tap asks xterm's existing providers to resolve the touched cell and opens the URL on the viewing device. Link mouse/touch gestures are consumed before terminal mouse reporting can forward them to tmux or the harness. Swipes, long presses, normal terminal clicks and Shift selection retain their respective behavior. Handlers and addon subscriptions are disposed with the terminal. No browser setting or command is changed on the Runner.

The browser's tmux attachment declares `RGB,hyperlinks` with tmux's per-client `-T` option. Without the hyperlink capability, tmux removes the embedded target of a named link before xterm receives it. This applies to writable and read-only viewers, including viewers joining an existing terminal. Reconnecting the browser terminal applies it to already-running agents; no harness restart, Runner setup or global tmux configuration change is needed.

## Verification

`SessionFilePreviewTests` covers encodings, size boundaries, binary data and Markdown rendering safety. `SessionFileApiTests` covers conversation permissions, deletion, inert responses and caching headers. `DeveAgentManager.Tests/Browser/file-viewer.mjs` checks both modes, loading/retry, fallback downloads and phone/light/dark layouts. `TerminalLinkTransportTests` checks actual tmux PTY output using the production attachment script, with a negative control that reproduces lost link targets. `terminal-links.mjs` checks direct and real-tmux output for URL and named-link clicks/taps, fragments, blocked protocols, swipe gestures and unchanged ordinary mouse reporting. Browser tests use an isolated development Manager with test-only credentials; see the existing shared-files browser test for its environment variables.
